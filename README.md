# 城市露天电影放映审批与设备巡检平台

Vue 3 + NestJS + PostgreSQL 实现的露天电影「申请—审批—备料扫码—现场巡检—异常协同—归还核销—街道复盘」全流程平台。

## 原始需求

建设城市露天电影放映审批与设备巡检平台，可采用 Vue 3、NestJS 和 PostgreSQL。社区、物业或商圈运营方提交放映申请时，需要记录放映日期、场地位置、预计观众、影片版权凭证、供电条件、银幕尺寸、音响数量、安保人员和雨天预案。文化审核人员确认影片授权和公共活动备案后，仓库按场次准备投影机、幕布、音箱、电缆、备用灯泡和防雨罩，设备领取时需要扫码核对成套状态。放映当天，现场负责人上传搭建照片、试播截图、噪声分贝、观众区域隔离和消防通道情况；若出现影片文件损坏、设备缺件、居民投诉噪声、临时降雨、观众超员、供电跳闸或商户要求延长活动，平台要让申请方、审核员、仓库、现场负责人、安保和财务围绕同一场放映处理。活动结束后，设备归还、损坏赔付、投诉处理、版权核销和补贴发放都回到该场次记录，便于街道复盘哪些场地适合继续安排夜间活动。平台还要支持不同活动主办方的信用记录、设备押金、志愿者签到和场地黑名单。街道文体岗要按活动时间线追踪申请、审批、出库、搭建、放映、投诉和核销，连续出现噪声或设备损坏的点位会影响下一轮审批。

## 技术栈

- 前端：Vue 3 + Vue Router + Axios + Vite
- 后端：NestJS 10 + TypeORM + JWT(passport) + class-validator
- 数据库：PostgreSQL 16（TypeORM `synchronize` 自动建表，启动自动种子数据）
- 部署：多阶段 Dockerfile（非 root 用户 `node` 运行 + `HEALTHCHECK`）、docker compose（app + db，仅发布 app 端口）

## 一键启动（宿主 docker compose）

```bash
cp .env.example .env        # 可按需修改 CC_PUBLISH_PORT
docker compose up -d --build
# 查看健康状态
docker compose ps
curl -s http://localhost:${CC_PUBLISH_PORT}/api/health
```

浏览器打开：`http://localhost:3119`（即 `http://localhost:${CC_PUBLISH_PORT}`）。

> 验证方式 = 宿主 `docker compose up`：应用服务端口通过 `ports: ["${CC_PUBLISH_PORT}:3000"]` 发布到宿主；
> PostgreSQL **不发布宿主端口**，仅在 compose 内网通过服务名 `db:5432` 访问。
> 取实际映射端口可用：`docker compose port app 3000`。

停止与清理：

```bash
docker compose down          # 仅停止删除容器
docker compose down -v       # 同时删除数据库卷（清空演示数据）
```

## 建议的端到端走查路径

1. `applicant` 登录 → 「提交放映申请」（黑名单场地在下拉中禁选，直接 API 提交也会被拦截）。
2. `reviewer` 登录 → 进入场次「申请与审批」→ 填写备案号 → 授权核验通过。
3. `warehouse` 登录 → 场次「设备出库/归还」→ 自动准备一整套 6 件 →
   到「设备领取扫码核对」逐个输入/扫描资产编码（资产编码见设备库存页），第 6 件核对完自动出库。
   - 扫入不属于本场成套的编码会被拒绝（成套核对失败）。
4. `site` 登录 → 「现场巡检/志愿者」→ 依次上传五类现场记录：
   搭建照片、试播截图、噪声分贝（>60dB 自动判不合格）、观众区域隔离、消防通道；
   五项齐备后「确认现场搭建与安全条件」→「开始放映」；可登记志愿者签到/签退。
5. 任一角色在「异常协同」发起七类工单之一：影片文件损坏、设备缺件、居民投诉噪声、临时降雨、
   观众超员、供电跳闸、商户要求延长；系统按类型自动分派主责角色，
   申请方/审核员/仓库/现场/安保/财务在同一工单留言协同并办结；
   确认成立的噪声/设备损坏/超员自动累加**点位风险计数**并扣减**主办方信用分**。
6. `site`/`security` 在场次「噪声投诉复盘」登记居民投诉：投诉楼栋、分贝读数、调低音量时间、安保沟通结果；
   若活动提前结束，登记结束时间后平台按「实际放映分钟/计划分钟」**重新计算街道补贴与商户协办费用**，
   并按分贝分档推导该点位后续最晚放映时间（≥70dB→20:00、≥60dB→20:30、其余→21:00）。
   `street` 在关闭前必须逐项勾选确认**居民沟通、音量调整、提前结束时间**；关闭后限制自动写入场地：
   下一次同场地申请会**自动带出最晚放映时间**（超时拦截）并**提示/强制提前降噪测试凭证**，缺凭证或超时均无法提交。
7. `warehouse` 逐件归还登记（完好/损坏/遗失 + 赔付）；
   `finance`/`reviewer` 做版权核销，`finance` 登记押金扣退、损坏赔付、补贴发放流水，最后「关单归档」。
8. `street` 登录 → 「街道看板」：KPI、状态分布、点位风险榜、主办方信用/押金、全区活动时间线；
   「场地与黑名单」可拉黑连续噪声/损坏点位（拉黑后该点位新申请被拦截），台账同时展示噪声复盘写入的「最晚放映时间 / 需提前降噪测试」限制。

## 核心业务规则

- **场次状态机**：草稿 → 待文化审核 → 审核通过/驳回 → 设备成套备好 → 扫码出库 → 现场搭建确认 →
  放映中 → 已完成核销。
- **成套扫码**：每场绑定一个 `kitNo` 套号的六件设备；领取时逐件扫码，编码必须属于本场成套，
  六件全部核对无误才允许出库。
- **现场五项门槛**：搭建照片、试播截图、噪声分贝、观众区域隔离、消防通道全部有合格记录，
  才能确认现场并开始放映；夜间噪声阈值 60dB。
- **风险联动**：噪声投诉 → 场地噪声数 + 投诉数、主办方信用 −8；设备缺件/损坏 → 场地损坏数、信用 −5；
  观众超员 → 投诉数、信用 −5。场地风险分 = 噪声×2 + 损坏×3 + 投诉；≥8 为高风险，街道可拉黑。
- **噪声投诉复盘**：放映中投诉由现场负责人/安保登记投诉楼栋、分贝读数、调低音量时间、安保沟通结果；
  活动提前结束时按「实际放映分钟 / 计划分钟（默认120分钟）」同比例重算街道补贴与商户协办费用，
  重算额回写场次作为补贴发放口径，并按分贝推导点位最晚放映时间。
  街道关闭投诉前必须三项全部确认（居民沟通、音量调整、提前结束时间）。
- **限制自动带出**：复盘关闭后写入场地 `latestShowTime` 与 `noiseTestRequired`；
  下一次同场地申请自动带出限制快照——放映开始时间晚于最晚时间、或未提交提前降噪测试凭证，申请均被拦截。
- **关单条件**：全部设备完成归还登记（含损坏/遗失）且版权已核销，财务才能关单；
  关单回写场地最近活动时间与主办方累计场次。
- **押金联动**：财务登记押金扣减/退还会实时联动主办方押金账户余额。

## 目录结构

```
.
├── backend/            # NestJS（实体/认证/场次/设备/巡检/异常/志愿者/核销/看板/种子）
│   ├── src/entities/   # TypeORM 实体
│   ├── src/modules/    # 业务模块
│   └── src/seed/       # 启动种子数据
├── frontend/           # Vue 3 + Vite
│   └── src/views/      # 登录/布局/场次列表/申请表单/场次详情/设备/场地/主办方/异常/看板
├── Dockerfile          # 三阶段构建，非 root 运行，内置 HEALTHCHECK
├── docker-compose.yml  # app + postgres，仅发布 app 的 ${CC_PUBLISH_PORT}
└── .env.example
```

## 本地开发（可选）

```bash
# 后端（需可访问 PostgreSQL）
cd backend && npm install && npm run start
# 前端（vite dev server 代理 /api -> localhost:3000）
cd frontend && npm install && npm run dev
```
